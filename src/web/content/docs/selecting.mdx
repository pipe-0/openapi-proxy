---
title: Selecting operations
description: How a variant says which operations it serves, today and when your API grows.
---

A variant is a selection of the project's operations. It is said with two lists, `include` and `exclude`, in a definition file and in the app alike:

> An operation is served when `include` is left out or names it, and `exclude` does not name it.

Each list names **tags** and **operations**. An operation is its method and its path, `GET /books/{id}`, so your document needs no `operationId`s. A webhook is `POST webhook:<name>`.

## Operations your API adds later

Your API will grow, and a selection has to say what happens then. That follows from how it is written.

| Selection | What it serves | An operation added later |
| --- | --- | --- |
| nothing | Everything | Served |
| `exclude` only | Everything except what is named | Served, unless it has an excluded tag |
| `include` with tags | Those tags | Served if it has one of the tags |
| `include` with operations | Exactly those | Not served |
| `include: {}` | Nothing | Not served |

So a tag is a rule: it covers what carries the tag today and what gets it next month. An operation named by itself is only itself.

For a public variant, write `include`. Nothing your backend adds then reaches the public by accident.

## In the editor

The app's editor, and the same editor that `openapi-proxy dev` serves, show a selection as checkboxes. A checked operation is served.

- **Checking a whole tag** includes the tag. It shows **Serve operations added later**, checked. Uncheck that to serve only what the tag has today: the tag becomes a list of its operations.
- **Unchecking one operation of an included tag** excludes that operation. The tag stays a rule.
- **The switch under the list** says what happens to operations your API adds later. **Hidden**: the selection has an `include`, and only what it names is served. **Served**: it has none, and everything is served that is not excluded. The line below the switch names the tags that are the exception.

The document on the right is what will be served. Nothing reaches the URL until you publish, or save into the file.

## What ends up in the document

The variant keeps the operations it serves and exactly what they reference: schemas, parameters, responses, request bodies, headers, examples, links, callbacks and security schemes. A schema that only an operation outside the selection used is left out.

Descriptions, examples and names are served as your document has them.

## A name the documents do not have

A selection can name a tag or an operation that is not in the documents: because the API that has it is not live yet, because it was renamed, or because of a typo. The variant serves the rest, and the name is reported, never refused:

- `openapi-proxy validate` and `deploy` print it as a warning, with the line it is on.
- The app shows "not found" on the variant, and the editor lists the operations.

When the document has the name, it is served. So a file can be deployed before the API it describes is.

## Finding the names

```sh
npx @pipe0/openapi-proxy operations
```

lists every operation with its tags, and the tags with how many operations each has. `--variant <slug>` says for each operation whether that variant serves it.
