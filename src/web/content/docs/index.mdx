Your backend generates one OpenAPI document for everything it does. openapi-proxy keeps the parts each audience should get and serves each selection at a URL of its own, as JSON or YAML, in OpenAPI 3.0 or 3.1. Your public docs read one URL, your SDK generator another, a partner a third.

## Two ways to make a project

**From a URL.** Your OpenAPI document is at a URL. The service reads it, keeps reading it, and you choose in the app what each audience gets.

**From your repository.** What each audience gets is written in a file next to your code. You serve it on localhost while you work, and deploy it from CI.

Both make the same thing: a project with variants at the same URLs. A project that started in the app can move into a repository later, without rebuilding anything.

## Which guide is yours

| You have | You want | Guide |
| --- | --- | --- |
| A document at a public or protected URL | A few variants that stay current by themselves, set up in a browser | [From a URL](/docs/from-a-url) |
| Several services, each with a document, or several audiences and environments | One API for your readers, and a document for each of them | [Several documents and audiences](/docs/several-documents) |
| A repository, a dev server and a pipeline | The selection in version control, variants on localhost, a deploy with every release | [In your repository](/docs/in-your-repository) |

## Four words

- A **workspace** is the people who share the projects. Signing in gives you one, and you invite colleagues into it.
- A **project** is one API as its readers know it: one OpenAPI document, or several merged into one. Its slug is the first part of every URL it serves.
- A **variant** is a selection of the project's operations, served at `/v/<project>/<variant>`. A variant is public, or private and read with a user API key.
- A **definition** says what a project is: its documents and its variants. It is what the app's editor saves, and it is the content of an `openapi-proxy.yaml` in a repository.

A variant keeps the operations you chose and exactly what they reference: schemas, parameters, responses, security schemes. Nothing else from your document ends up in it.
