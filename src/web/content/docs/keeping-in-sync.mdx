---
title: Keeping in sync
description: How the proxy notices that your API changed, how often it looks, and how to make it look more often.
---

Variants are served from a stored copy of your document. A timer checks your API for a new one, and how often it does depends on one thing: what a check costs your API.

- **Every 5 minutes**, if your API can say that nothing changed without sending the document again: it sends an `ETag` or `Last-Modified` with the document.
- **Once an hour**, if it cannot. Every check then makes your API send the whole document, and an OpenAPI document does not change often enough to ask for that more.

There is nothing to configure. A project's settings list its documents and say which of the two applies to each.

A request for a variant never checks. It is answered from the stored copy at once, whatever your API is doing at that moment.

- A failing API is checked again five minutes later, and once an hour after that until it is back. Variants keep being served from the last good copy.
- Only projects with at least one variant are checked.

## Right after a deploy

When you know your API just changed, say so, and the proxy checks at once: **Check for updates now**, in the project's settings. The answer says which operations were added, removed or changed.

Readers of a public URL cannot ask for a check: they are anonymous, and how often your API is called is not theirs to decide.

## What a check does

A check stops at the first step that answers "has the document changed?":

1. **Conditional request**, if your API sent an `ETag` or `Last-Modified` with the document. The proxy asks "anything newer than this?", and a `304` answer carries no body. See [Sending an ETag](/docs/etag).
2. **Download**, otherwise. The proxy fetches the whole document and compares it with the stored one. If the bytes are the same, nothing else happens.

## What it costs to do nothing

Without an ETag everything still works. Changes show up within the hour, not within five minutes, unless you use Check for updates now. An ETag makes the proxy look twelve times as often, usually with one line of code.

## In a project with several documents

A check looks at every document of the project. So the project is checked as often as its costliest document allows: every 5 minutes only if all of them can be checked cheaply.
