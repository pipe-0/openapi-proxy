---
title: When your API changes
description: What a variant serves after your API changed, and how you hear about it.
---

The proxy reads your document again and again, so it can tell what moved. A variant always serves a valid document, and you are told what changed.

| In your API | What is served | What you see |
| --- | --- | --- |
| A selected operation disappears | The rest. It is served again if it comes back. | A notice in the editor, and an email |
| New operations appear | Hidden or served, as [your selection says](/docs/selecting) | A "new" marker on the variant, and an email |
| An operation changes | The new version | An email, if a variant serves it |
| The document cannot be fetched, or is invalid | The last good copy | "Check failed" on the project, with the reason |

A change counts per operation and includes what the operation references. A field added to a schema is reported for the operations that use that schema, and for no others.

## Email

Emails go to the address you signed in with. In each project's settings, under **Email about changes**, you choose how much you want for that project:

- **Nothing.**
- **What my variants serve**: new operations, and changes and removals that touch something a variant serves.
- **Everything**: every operation that is added, changed or removed.

The setting is yours alone. Your colleagues choose for themselves.

Every document is checked at least once an hour, also when nobody reads a variant. You hear about a new operation before your next docs build, not after it.
