---
title: URLs, formats and versions
description: The URLs a consumer fetches, the formats and OpenAPI versions behind them, and the response headers.
---

Every variant has a URL. Docs renderers, SDK generators and contract tests fetch it like any other OpenAPI document.

```
GET /v/<project>/<variant>              JSON, or YAML if the Accept header asks for it
GET /v/<project>/<variant>.json
GET /v/<project>/<variant>.yaml
GET /v/<project>/<variant>/3.0.json     OpenAPI 3.0
GET /v/<project>/<variant>/3.1.yaml     OpenAPI 3.1, as YAML
```

The URL picks the representation: the format by its extension, the OpenAPI version by a path segment. `openapi-proxy dev` serves the same paths on localhost.

Every project also serves its documents as they are, at `/v/<project>/original`, in the same formats and versions. Who may read it is set like for any variant: see [original](/docs/configuration#original).

JSON keeps the formatting of your document: a minified source is served minified, an indented one indented.

## Response headers

| Header | Value |
| --- | --- |
| `ETag` | Changes whenever the served bytes can: a new document, a change to what the variant serves, another format or version. |
| `Cache-Control` | `public, max-age=60, stale-while-revalidate=300`. For a private variant, `private, no-cache`. |
| `X-Proxy-Source-Status` | `fresh`, or `stale-error` when the last check of a followed source failed and the last good copy is served. |
| `Access-Control-Allow-Origin` | `*`, because documentation tools fetch from other origins. |

A request with `If-None-Match` gets a `304` when nothing changed, and `HEAD` is answered without a body.

A request for a variant is always answered from what the service has stored. It never makes the service fetch your API. See [Following a URL](/docs/following-a-url) for when the stored documents change.

## Public and private

A public variant is read by anyone with its URL. A private one answers `401` without a user API key and `403` with a key that is not for it. See [Private variants and keys](/docs/private-variants).

## OpenAPI versions

Your framework generates one version of OpenAPI. The tools that read it do not all agree: a documentation site may want 3.1, an API gateway or an older generator may only take 3.0. So every variant of an OpenAPI 3.0 or 3.1 document is served in both, and the reader picks one with the URL.

- Without a version in it, a URL serves the version your document has. A project of several documents has the highest version among them. A document that is not converted is not rewritten at all.
- A URL with a version in it keeps serving that version when your API moves from 3.0 to 3.1 or back. Use it for a reader that takes only one.

There is nothing to set up. A version is converted the first time someone asks for it, and stored.

### From 3.0 to 3.1

Nothing is lost. The few things 3.0 says its own way are said the way JSON Schema does:

| In 3.0 | In 3.1 |
| --- | --- |
| `type: string`, `nullable: true` | `type: [string, "null"]` |
| `minimum: 5`, `exclusiveMinimum: true` | `exclusiveMinimum: 5` |
| `example: x` on a schema | `examples: [x]` |

### From 3.1 to 3.0

3.0 schemas are an older, smaller language. What has an equivalent is translated:

| In 3.1 | In 3.0 |
| --- | --- |
| `type: [string, "null"]` | `type: string`, `nullable: true` |
| `anyOf: [X, { type: "null" }]` | `X` with `nullable: true` |
| `const: x` | `enum: [x]` |
| `exclusiveMinimum: 5` | `minimum: 5`, `exclusiveMinimum: true` |
| `examples: [x, y]` on a schema | `example: x` |
| a `$ref` with other keywords next to it | `allOf: [{ $ref }]` with those keywords |
| `contentMediaType: application/octet-stream` | `format: binary` |
| `webhooks` | `x-webhooks`, which Redoc and others read |

What has no equivalent is removed: `patternProperties`, tuples (`prefixItems`), conditions (`if`, `then`, `else`), `unevaluatedProperties` and a few more. The editor says what was left out of the variant on screen and how often, so you know what a 3.0 reader will not see.

### What is not converted

- A Swagger 2.0 document cannot be a source.
- A 3.2 document is served as it is, at the URL without a version. For such a project `/3.0` and `/3.1` answer `404`.
